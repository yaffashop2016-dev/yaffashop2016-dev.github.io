# 採購、庫存與訂單追蹤系統使用手冊

本系統協助管理供應商與客戶資料、產品成本與售價、供應商詢價、客戶報價、採購訂單、收貨驗收、庫存、銷售出貨，以及應收／應付帳款。本文依照新手初次設定與日常作業順序說明功能和建議流程。

## 開始使用前

1. 使用瀏覽器開啟本資料夾中的 `index.html`。
2. 系統資料儲存在目前瀏覽器的 `localStorage`，不會自動同步到其他瀏覽器或電腦。請固定在同一台電腦、同一個瀏覽器與相同的開啟方式操作。
3. 第一次使用時，先到「設定」填妥公司資料，再建立供應商／客戶及產品資料。
4. 每日作業結束、匯入備份或大量修改資料前，建議到「設定」按「備份全部」，將 JSON 備份檔存到安全位置；設定頁也可還原 JSON，或匯出供應商、產品與訂單明細 Excel。

> 清除瀏覽器資料、改用其他瀏覽器或電腦，可能會使目前瀏覽器中的資料無法使用。備份檔是搬移或還原資料的主要方式。

## 新手建議設定順序

1. **設定公司資料**：前往「設定」，填公司名稱、統編、電話、聯絡人、匯款資訊及付款條件。這些資料會帶入新建立的客戶報價單。
2. **建立往來對象**：前往「往來對象管理」，新增供應商或客戶，盡量補齊聯絡方式、地址、付款方式和月結條件。
3. **建立產品資料**：前往「+ 新增資料」或「產品報價查詢」新增產品，設定供應商、規格、幣別、進價、售價、稅別、運費與庫存門檻。多品項合成一個銷售／採購單位時，商品類型統一選「產品組合」，再依後續流程選擇組合處理方式；拆分包裝由系統依基礎產品編號及換算數量建立關聯。
4. **檢查舊資料**：若是由舊版資料開始使用，請檢查產品售價及付款條件是否完整。歷史交易金額仍保留原紀錄；舊產品的單一價格遷移為進價，售價可能需要補填。
5. **建立備份**：設定完成後按「備份全部」保存第一份基準資料。

## 各頁籤功能

### 概況與營運報表

- 概況卡片顯示供應商、產品、客戶報價、採購項目、訂單及詢價單數量；下方彙總報價、詢價、付款和物流狀態。
- 營運報表以出貨異動分析指定日期區間的銷售收入、成本、毛利和數量，並提供依商品、客戶及期間的毛利分析，以及商品表現、訂單期間彙總、商品銷售及滯銷報表。銷售收入優先採應收明細未稅金額，應收單折扣按品項收入比例分攤；商品毛利不含未分攤運費。未關聯應收明細的舊出貨則依出貨售價計算。
- 庫存分析彙總目前庫存數量、可用數量及金額，可分別依倉別和產品分類檢視；庫存金額以庫存主檔成本為準。
- 應收及應付帳齡依今日未結餘額分為未到期、逾期 1-30 天、31-60 天、61-90 天及 90 天以上；未設定到期日的單據獨立列示。
- 採購統計依月份及供應商彙總指定日期範圍的訂單數、採購數量、採購金額、已建應付、已付及應付餘額。應付金額只包含已建立的應付單。
- 按「匯出分析報表」可下載含商品／客戶／期間毛利、倉別／分類庫存、應收／應付帳齡及採購統計的多工作表 Excel。上方日期範圍適用於銷售及採購；庫存為目前存量，帳齡以今日為基準。
- 「訂單彙總」可切換每日、每週或每月；滯銷報表列出有可用庫存且至少 30 天未售出或從未售出的商品。
- 出貨日期區間會篩選營運報表。歷史出貨若沒有保存成本，毛利可能以目前庫存平均成本估算；新出貨會記錄出貨當下成本。

### 往來對象管理

- 在同一頁新增或維護供應商和客戶，以「角色」切換資料欄位，並可依角色篩選。
- 可用名稱、統編、聯絡人、電話、Email 或地址搜尋；資料可修改或刪除。
- 供應商可記錄月結天數、關帳日、指定付款日、收款銀行、分行及匯款帳號；客戶可記錄關帳日、指定付款日及收款資訊。
- 往來對象的付款條件會在建立應收／應付時作為試算依據；建立的單據會保留交易當下的條件快照。

### 產品報價查詢與新增資料

- 產品清單可搜尋產品名稱、規格或供應商，並查看進價、售價、稅別與參考運費；可從產品列進行產品維護。
- 新增或編輯產品時可維護 SKU、條碼、分類、品牌、單位、安全庫存、補貨點、交期、產品網址、備註及啟用狀態。
- 進價與售價分開管理：採購及手動入庫使用進價；客戶報價及銷售出貨使用售價。售價以 NTD 設定，未設定時須按實際交易輸入，不會自動用進價代替。
- 採購幣別可選 NTD 或 RMB。人民幣產品須設定「1 RMB = X NTD」匯率；進價和參考運費使用所選幣別。NTD 匯率固定為 1。
- SKU 需保持唯一。停用產品不能加入新採購；可用量低於補貨點時會顯示低庫存，未設定補貨點則沿用安全庫存。
- 「+ 新增資料」可建立供應商及產品資料。產品也可從供應商詢價紀錄轉入正式產品。
- 包裝產品以「基礎產品編號＋每包基礎單位數」作為識別，不以名稱或規格文字判斷相同產品；規格文字只供人員辨識與顯示。拆分時相同換算關係會重用既有產品，不會因文字不同另建一筆。
- 包裝產品的進價與售價是該包裝自己的價格。建立新包裝時，系統依拆分數量從來源庫存價格換算初始價格；既有包裝則沿用其原有產品資料與價格。基礎單品日後調價不會自動改寫包裝售價。
- 產品 Excel 會包含「包裝基礎產品編號」及「每包基礎單位數」欄位；匯入相同基礎產品及換算量時會重用產品。已有庫存或交易引用的產品不應更改產品編號或包裝身分；系統會阻止受引用產品的刪除，以及匯入變更包裝身分的操作，以保護歷史關聯。
- 舊資料不會依規格文字自動推測包裝比例，也不會自動改寫庫存或歷史交易關聯。遷移時需人工確認每筆舊包裝所屬基礎產品和每包數量；不確定的資料請維持原狀。

#### 舊包裝資料遷移流程

1. 先按「備份全部」下載 JSON 備份，確認可還原後再匯入資料。
2. 從頁面匯出產品 Excel，另存為 UTF-8 編碼 CSV；保留「系統ID」及其他既有資料欄位。
3. 逐筆確認舊包裝的基礎單品，並在「包裝基礎產品編號」填入該單品的產品編號，在「每包基礎單位數」填入正整數換算量（至少 2）。兩欄需同時填寫；基礎產品本身不可是另一個包裝或組合包。
4. 確認基礎產品列也在系統中或同一份匯入檔內，且包裝列的系統編號與基礎產品編號不同。不要只憑「10 入」、「一箱」等規格文字推算或配對。
5. 在頁面上方選擇 CSV 匯入檔，確認匯入筆數與警告。若資料不正確，停止後續操作並使用匯入前備份還原或修正 CSV 再匯入。
6. 匯入只建立或更新產品主檔，不會把舊庫存或歷史交易自動改掛到新包裝產品。完成後應逐筆檢查包裝關聯及庫存歸屬；需要更正既有產品的包裝身分時，先處理其引用關係，不要以規格文字強行對應。

#### 客戶報價使用包裝產品

1. 建立或編輯客戶報價時，在產品搜尋欄輸入至少 2 個字，可用產品名稱、規格、產品編號、SKU 或條碼搜尋。
2. 搜尋結果若為包裝產品，核對畫面上的基礎產品編號、每包數量及規格，再選取正確的產品編號。
3. 報價預設使用該產品自己的售價及進價；未設定售價時應核對並輸入本次報價，不要直接將單品售價當作包裝售價。
4. 報價項目會保存建立時的價格快照。之後修改產品價格不會追溯改寫已儲存的報價；若要使用新價格，請在報價中重新確認並更新金額。

### 供應商詢價單（向供應商詢問）

1. 選「建立新詢價單」，填寫供應商、詢價日期、狀態、聯絡資訊及備註。
2. 加入一項或多項待詢問產品／服務，填寫規格、預估數量及單位後儲存。
3. 依供應商回覆更新狀態：等回覆、已回覆、價格高、無供貨或已轉正式產品。列表可搜尋供應商、產品、備註或單號，也可依狀態篩選。
4. 可匯出單筆詢價 Excel；確認可供貨的品項可轉成正式產品資料。

### 客戶報價單（提供給客戶）

1. 在「客戶報價」按「建立新報價單」。
2. 輸入客戶名稱，從搜尋建議中選取客戶；客戶主檔聯絡人、電話和 Email 會帶入報價單，也可依本次對接窗口調整。填寫報價日期、狀態和備註。
3. 搜尋並加入產品，確認數量及報價金額。系統會即時計算毛利；若標記未成交，需填寫未成交原因。
4. 儲存後聯絡資訊會保留在該報價單，且可在列表查看、修改或匯出報價 Excel；也可搜尋客戶或報價單號，依狀態、日期區間篩選。
5. 客戶確認成交後，使用「轉採購」將報價品項帶入採購清單，再按一般採購流程下單。

### 採購清單與下單

1. 在「產品報價查詢」找到產品，將需要採購的品項加入採購清單。客戶報價成交轉採購也會將品項加入此清單。
2. 前往「採購單管理」，逐項確認勾選狀態、單價、數量、稅別、運費、幣別匯率及備註。總額只計算已勾選的項目。
3. 可匯出目前清單 Excel。按「下單已選項目（建立訂單）」後，系統會依供應商分成不同採購單；下單前請仔細核對價格、匯率、數量和稅別。
4. 訂單會保存下單當時的價格、匯率、產品資料及組合包 BOM 快照；之後修改產品主檔或匯率不會改變已建立的訂單。

### 訂單追蹤

- 可搜尋產品、供應商、發票或供應商原始單號，並依物流狀態篩選；展開「進階篩選」可依付款狀態、下單年及月份篩選。
- 訂單卡片可維護訂單狀態、付款／物流資訊、日期及備註。「進階訂單資料」中包含供應商單號、報價單號、發票、物流商、物流單號、出貨日、訂單折扣及溝通備註。
- 訂單備註可用多行文字記錄與供應商的溝通過程；修改後會自動儲存。折扣會影響訂單總額；若訂單已轉為應付，折扣會鎖定。
- 依訂單卡片上的操作可將訂單轉入庫存、建立應付，或執行系統允許的取消／撤銷等操作。影響交易或庫存的操作會要求確認，請先閱讀確認提示。
- 可匯出訂單／發票明細 Excel。訂單明細中的總金額每張訂單只會在第一筆品項列顯示一次，方便直接加總。付款狀態若已連結應付帳款，會由應付單及付款紀錄推導。

### 收貨與驗收

1. 訂單到貨後前往「收貨驗收」，找到對應採購單，逐項輸入本次實收、合格及拒收數量，並填寫收貨日期、倉別和備註。
2. 只有驗收合格數會建立庫存批次；可分批收貨。拒收品項後續補貨時，再新增一次收貨紀錄。
3. 確認合格數量後提交收貨，並在收貨紀錄區檢查資料。收貨紀錄可匯出 Excel。
4. 如需更正收貨，請在收貨紀錄按「撤銷收貨並扣回入庫」。此操作會一併刪除收貨紀錄、扣回該收貨建立的庫存與批次，並還原訂單的實收／合格／拒收數量；完成後可重新收貨，不需再到訂單頁撤銷轉入。
5. 若過去曾手動刪除收貨建立的庫存，系統會提示該收貨的庫存、異動或批次資料不完整。確認相關庫存已刪除且未出貨後，可繼續修復撤銷；系統只扣回仍存在且可核對的庫存，不會補造缺少的庫存或成本資料。訂單收貨數量還原後即可重新收貨。
6. 已出貨／占用的收貨庫存或已有有效應付單的收貨不可撤銷；須先處理出貨或應付。已作廢的應付不阻擋撤銷。有收貨紀錄的採購單也不能直接取消、刪除或修改數量／成本，需先在收貨驗收逐筆撤銷。請勿直接刪除仍關聯收貨紀錄的庫存，系統會阻止此操作。
7. 訂單頁的整單「撤銷轉入」僅供沒有收貨紀錄的舊式整單轉入使用；分批收貨一律在收貨驗收逐筆撤銷，避免重複扣回庫存。

### 產品組合與處理方式

商品類型只提供一種「產品組合」，代表多個一般單品依 BOM 合成一個採購／銷售單位。建立組合時先選每組包含的單品與數量，再選擇後續處理方式；兩種方式不可混為一種庫存流程：

- **採購收貨時拆成單品**（舊資料類型 `kit`）：採購訂單以組合單位下單，收貨驗收合格時依訂單保存的 BOM 拆成單品庫存，組合本身不建立庫存。每項單品需設定成本分攤權重。
- **銷售時扣組成品**（舊資料類型 `sales-bundle`）：組合有自己的獨立售價；銷售時依 BOM 扣除組成單品庫存，應收與出貨仍記錄組合產品及其成交價。也可先組裝為組合庫存，再直接銷售已組裝品。

新介面以單一「產品組合」商品類型呈現，並以「組合處理方式」區分上述流程。系統內部保留舊資料類型值，確保既有訂單、庫存和交易的處理方式不變。組合內容只能選取已建檔的一般單品，不能選另一個產品組合，避免 BOM 遞迴。產品 Excel 匯出會以「產品組合」及「組合處理方式」兩欄記錄；匯入仍支援舊版「組合包」與「促銷銷售組合」資料。

#### 採購組合收貨拆套

1. 先建立組合內會實際入庫的單品。
2. 新增產品時選擇「產品組合」，處理方式選「採購收貨時拆成單品」，加入各單品並設定每組數量及成本分攤權重。新增組合單品時，需從候選清單點選正式產品；只輸入文字不算完成選取。
3. 將組合包加入採購清單並建立訂單。下單時保存的 BOM 快照會用於該筆訂單，即使日後修改組合內容也不影響舊單。
4. 收貨驗收合格後，系統依該訂單 BOM 將組合包拆成單品庫存；組合包本身不另外建立庫存。
5. 一般品項的入庫成本會把明細運費平均分攤至採購數量，例如單價 60 元、數量 100、運費 200 元，入庫成本單價為 62 元。組合包的採購成本及運費則依 BOM 成本權重分攤至拆出的單品。
6. 若拆套產生的單品已出貨，系統會阻止撤銷該收貨，以保護庫存數量與成本紀錄。

#### 銷售時扣除組成品（A、B 組成 C）

此處與採購組合使用相同的「產品組合」類型，但選擇不同處理方式：採購組合在收貨時拆成單品；此組合以 C 的獨立售價銷售，銷售時扣除 A、B，或先組裝成 C 再從 C 庫存出貨。

1. 到「+ 新增資料」建立產品 C，商品類型選「產品組合」，處理方式選「銷售時扣組成品」，輸入組合名稱、規格、單位，以及 C 自己的售價。組合價格不會自動加總 A、B 售價。
2. 在促銷組合內容中，搜尋並點選 A、B 等已建檔的一般產品，填寫每一組需要的數量。不可選擇採購組合包或另一個促銷組合，避免組合遞迴。
3. POS 或客戶出貨單銷售時，若選「組成品扣庫」，系統依 C 的 BOM 計算可組數、分配實際庫存批次並扣除 A、B；應收明細及出貨紀錄仍以產品 C 和 C 的成交價格記錄。
4. 若要銷售已組裝好的 C，先到「庫存管理」選「組裝促銷組合」，指定 C、組裝數量及 C 的入庫倉別。組裝會依 BOM 扣除可用 A、B，並以組成品平均成本計算 C 的庫存成本。
5. 組裝完成後，在 POS 或出貨單選擇 C 的「已組裝庫存」品項，即扣除 C 本身庫存；每筆銷售可自行選擇組成品扣庫或已組裝庫存，不會把兩種庫存來源混為一筆。
6. 退回以組成品扣庫方式售出的 C，系統依原出貨快照將對應 A、B 數量退回原庫存項目及倉別，並建立退貨批次，不會建立虛擬 C 庫存；退回已組裝 C 則回補原 C 庫存。退貨金額依原 C 銷售明細處理。
7. 組裝、銷售或退貨若發生庫存不足或儲存失敗，系統會阻止提交或還原本次庫存與交易變更。請檢查「庫存異動」中的組裝、組成品扣庫與退貨紀錄。

產品編輯可以更新未來交易使用的促銷組合 BOM；既有出貨／退貨使用出貨時保存的組成品快照。已被庫存、交易或其他產品引用的產品不可更改產品類型，以避免破壞歷史關聯。

### 庫存管理

- 庫存列表顯示批次、可用數量、成本及庫存金額，可搜尋庫存編號、訂單編號或產品，並依正常、低庫存或缺貨篩選。
- 可直接從庫存品項檢視批次、記錄出貨或進行適用的庫存操作。
- 展開「進階操作」可手動建立入庫（適合期初庫存或無採購單情況）、依庫存編號盤點調整、拆分或逆向換算包裝，或刪除庫存。包裝換算會依基礎產品及每包數量判斷目標產品；規格文字只供顯示。系統同步調整來源／目標庫存、批次、成本及異動；儲存失敗會復原操作。也可匯出庫存清單與異動記錄。
- 盤點調整、拆分包裝及刪除會影響庫存，請先核對庫存編號、數量與成本，再確認操作。

#### 拆分／換算包裝操作流程

1. 先確認基礎產品與包裝產品已建檔且關聯正確。開啟「庫存管理」的「進階操作」，依庫存編號選擇「拆分包裝」；核對視窗顯示的來源產品與庫存。
2. 在「拆分來源數量」輸入要扣除的來源包裝數，在「拆分後產生數量」輸入換算後的目標包裝數。兩者都必須是大於 0 的整數，來源數量不可超過現有可用庫存。
3. 系統依下式換算目標每包基礎單位數，並即時顯示目標產品編號：

   `目標每包基礎單位數 = 拆分來源數量 × 來源每包基礎單位數 ÷ 拆分後產生數量`

   單品視為每包 1 個基礎單位。換算結果必須是整數；例如 1 包 10 入可換成 2 包 5 入，也可換回 10 個單品。若不能整數換算，請調整數量，不要用小數包裝補差。
4. 檢查預覽中的目標產品編號及換算量。已有相同基礎產品與換算量時會顯示並重用原產品編號，即使本次輸入的規格文字不同也不會另建產品；沒有符合產品時，預覽會顯示預計建立的編號。預覽只供檢查，不會建立產品或改動庫存。
5. 「規格名稱（僅供顯示）」可填寫方便辨識的文字，不能用它設定換算比例。逆向拆回單品時會使用原基礎產品的產品編號、規格、單位及產品價格；換算到既有包裝時則使用該包裝既有主檔資料及價格。新建包裝的初始產品價格會依拆分比例換算。
6. 再次核對來源數量、目標數量、預覽編號及備註後按確認執行；不執行時關閉視窗或取消確認即可，不會建立包裝產品或異動庫存。成功後來源庫存扣減、目標庫存增加，並記錄批次、成本及庫存異動；來源庫存不足、批次資料不一致或換算無效時操作會被拒絕。
7. 成功後數量欄會清空，避免沿用相同表單重複提交。若儲存或執行失敗，產品、庫存、批次及異動資料會復原；看到失敗提示後先確認資料與庫存，再決定是否重試。

### 銷售出貨

1. 前往「應收／應付」，展開「建立客戶出貨單並產生應收款」。
2. 搜尋並選取客戶，填出貨日期、發票資料及付款條件；系統會依客戶設定試算帳期與到期日，也可按實際交易調整。出貨地址預設帶入客戶地址，可再修改；另可填物流、物流編號、送貨人及出貨備註。
3. 新增庫存品項，核對可用數量、出貨數量、售價與稅別，並填運費及折扣。
   促銷組合可在下拉選單選「組成品扣庫」，或選實際 C 庫存（標示「已組裝 C 庫存」）；出貨明細及售價一律記錄產品 C。
4. 按「確認出貨並建立應收」前再次確認客戶、品項和金額。確認後會扣減庫存、建立出貨異動與應收單；出貨資訊會同步保存於應收單及關聯出貨紀錄，並可從應收單或出貨紀錄互相查看；此交易不應以一般庫存刪除方式回復。
5. 「出貨」頁可搜尋出貨記錄、查看物流與送貨資訊、設定日期區間及匯出包含物流資料的出貨 Excel。也可從庫存品項使用「銷售出貨」快速帶入品項。
6. 每筆「出貨紀錄」都可單獨匯出 Excel 出貨單，或使用 A4 版面列印／另存 PDF；出貨單會帶入公司設定、客戶、物流、品項與出貨備註。

### POS 收銀

1. 前往「POS 收銀」，可在條碼欄掃描／輸入產品主檔條碼並按 Enter 快速加入商品，也可從可用庫存清單搜尋後點選。同一庫存重複掃描或點選會合併數量；若該商品分布多個倉別，請在清單選擇實際出貨倉別。
2. 客戶可選擇既有客戶，或保留「現場客」。售價預設帶入產品設定的售價，結帳前可逐項核對／修改售價、數量及稅別；售價未設定時請先輸入本次成交價。
3. 選擇交易日期和現金、匯款或刷卡收款方式，確認總額後按「確認收款並結帳」。系統會建立已收清的應收銷售單、登記收款、扣減對應庫存並新增 POS 出貨異動。
4. POS 交易會與「應收／應付」、「出貨」、「庫存管理」及營運報表共用資料；若庫存不足或儲存失敗，交易不會留下部分扣庫存或帳款紀錄。
5. 促銷組合會分別顯示「組成品即時扣庫」和已組裝 C 的庫存選項；核對該次銷售要消耗的來源後再加入購物車。兩種模式使用同一個 C 售價。

### 應收／應付帳款

- **應付**：採購訂單全部驗收合格後，從訂單建立應付單。系統依供應商付款條件試算帳期與到期日，並防止同一訂單／供應商重複轉入。
- **應收**：完成銷售出貨時同步建立應收單，保存客戶資料與付款條件快照。
- 帳款清單可搜尋客戶／供應商或單號，並檢視應收、應付餘額及付款狀態。
- 可對帳單分次登記收款或付款，填日期、金額、現金／匯款／支票／刷卡方式及備註；也可依畫面提供的操作修改或刪除帳單、列印 A4 單據。
- 應收及應付可分別匯出 XLSX。已連結訂單的付款狀態由帳單金額和實際付款紀錄自動計算為未付款、部分付款或已結清。
- 刪除應收單會回補庫存並移除相關出貨異動；操作前請仔細閱讀確認及影響提示。

### 公司設定

「設定」可維護公司名稱、統編、電話、聯絡人、匯款銀行、帳號及付款條件，也可設定入庫倉別清單。倉別每行一個名稱，第一項為預設倉別；收貨驗收會以此清單提供下拉選擇。未設定清單的舊資料預設使用「總倉」。設定會包含在 JSON 備份中。

客戶報價會保留建立當下的公司資料快照；舊報價若無快照，匯出時使用目前公司設定。

## 金額、稅務與交易資料

- 系統金額以 NTD 為主。RMB 採購按採購當下匯率換算，訂單會保存原幣價格與匯率。
- 採購或出貨品項可依交易選擇含稅、不含稅或不計稅；應稅項目以 5% 計算營業稅。帳款單層級的稅額、總額、折扣及收付款以整數元保存。
- 交易會保存建立當下的重要價格與產品資料快照，避免日後修改產品主檔而改變歷史交易。
- 組合包成本分攤依採購時保存的 BOM 與權重計算，詳見「採購組合包拆套入庫」。

## 匯出、備份與還原

- 頁面頂部可匯出供應商、產品及訂單明細 Excel；各功能頁另提供報價、詢價、採購清單、收貨、庫存、出貨及應收／應付等資料的 Excel／XLSX 匯出。
- 「備份全部」會下載包含系統資料的 JSON，適合完整備份或搬移資料；Excel 匯出主要供檢視與報表使用，不等同完整系統備份。
- 還原前請先按「備份全部」。使用頂部「還原」選擇先前的 JSON 備份，系統會檢查檔案並詢問是否覆寫目前資料。還原會取代目前瀏覽器中的系統資料，請確認檔案與瀏覽器無誤後再繼續。

## 建議每日作業流程

1. 開啟「概況」，檢視待處理報價、詢價、付款與物流狀態。
2. 新需求先建立客戶報價或供應商詢價；確認成交或供貨後，更新狀態並轉入對應後續流程。
3. 採購前確認供應商、產品、進價／匯率、稅別與庫存狀態；在採購清單核對勾選項目後建立訂單。
4. 訂單送出後，在「訂單追蹤」維護供應商單號、物流、日期及溝通紀錄。
5. 到貨後逐項驗收；合格品建立庫存，並在所有品項驗收完成後建立應付。
6. 銷售時從庫存建立客戶出貨，核對可用量與售價；出貨會扣庫存並建立應收。
7. 在「應收／應付」登記實際收付款，定期檢查逾期與未結清帳款。
8. 工作結束或進行大量資料調整前，匯出 JSON 備份並妥善保存。

## 操作前請留意

- 「備份全部」與 Excel 匯出用途不同；需要完整還原資料時使用 JSON 備份。
- 建立訂單、收貨、出貨或帳款前，先核對對象、日期、數量、金額、稅別及付款條件。
- 收貨、出貨、庫存調整和刪除可能彼此連動。若系統阻止撤銷或修改，請勿繞過限制直接改資料；先確認相關收貨、出貨、庫存批次及帳款是否已建立。
- 新增或修改往來對象及產品主檔，不會自動更改已保存的歷史交易快照。
